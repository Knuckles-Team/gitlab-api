| `CONN-GITLAB-API-R006.1` | **Typed GraphQL tools return a typed failure category.** Since 27.3.20 the typed `gitlab_graphql_ops_*` tools call the SDK GraphQL client directly, so a query error answers only `Query execution failed: TransportQueryError` (live check 2026-11-07: `gitlab_graphql_ops_update_merge_request` on a missing merge request). The connector passes a GitLab `error_classifier` to the SDK client (`SCION-CENTRALIZED-CAPABILITIES-R006.6`). It maps GitLab's stable answers to the closed categories: the missing-or-unauthorized resource answer to `not_found`, a forbidden answer to `forbidden`, argument and input validation answers to `invalid_input`, and anything else to `unknown`. The tool error then reads `Query execution failed: TransportQueryError (<category>)` and carries no GitLab text. A mutation that returns its own `errors` list (for example `mergeRequestUpdate.errors`) raises `invalid_input` instead of returning a success payload. Child of `CONN-GITLAB-API-R006`. Caller chain: MCP tool `gitlab_graphql_ops_update_merge_request` → `gitlab_api/gitlab_gql.py::update_merge_request` → `execute_gql` → SDK `GraphQLClient.execute`. Shape: one classifier function beside the client construction in `gitlab_api/gitlab_gql.py`; no new module. Depends on: `SCION-CENTRALIZED-CAPABILITIES-R006.6`. | `tests/test_graphql_error_category.py::test_missing_merge_request_update_is_not_found_without_server_text`. |
