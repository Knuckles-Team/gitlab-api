A CI variable `value` is redacted. `CreatedDeployToken`, parsed only by `create_project_deploy_token` and `create_group_deploy_token`, returns the new `token` once; those two docstrings, which are the tool descriptions, say they return a secret. Proving test: `tests/test_response_models_hide_secrets.py`. Caller chain: the `gitlab-mcp` console script loads `gitlab_api:connector` (`gitlab_api/__init__.py:9`), whose Api methods (`gitlab_api/api/api_client_projects.py`, `api_client_users_groups.py`) parse every GitLab reply into these models before the SDK serves it. Shape: the secret filter runs in the model, so no tool, present or added, can pass a secret field through. | The test instantiates every response model with secret-named keys and finds none in `model_dump`; a project loses `runners_token`; a read deploy token has no `token` and a created one has it. Test: `tests/test_response_models_hide_secrets.py::test_serializing_a_model_never_emits_a_secret_field`. |
